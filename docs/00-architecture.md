## 1. فهمي للنظام

أنت لا تطلب «قارئ تغريدات». أنت تطلب **نظام استخبارات معرفية شخصي** مهمته:

| المرحلة | الوصف |
|---|---|
| **Ingest** | استقبال روابط/حسابات من 6 أنواع مصادر (X، YouTube، GitHub، مواقع، مقالات، روابط يدوية) |
| **Normalize** | تحويلها كلها إلى كيان واحد موحّد اسمه `ContentItem` مهما اختلف المصدر |
| **Judge** | الحكم على الأهمية قبل التخزين — الرفض هو الوظيفة الأهم، لا القبول |
| **Understand** | فهم عميق: ماذا يقول، لماذا يهم، ما المصطلحات، ما الروابط، ما الخلاصة من النقاش |
| **Classify** | تصنيف متعدد الأبعاد (6 محاور مستقلة، وليس تصنيفًا واحدًا) |
| **Deduplicate** | تجميع الخبر الواحد المكرر في 6 مصادر في بطاقة واحدة |
| **Rank** | ترتيب مزدوج: تفاعل خارجي + قرب شخصي من اهتماماتك |
| **Retrieve** | بحث وفلترة ومجموعات ورجوع سهل بعد شهور |
| **Learn** | التعلم من Like/Bookmark لتعديل الترتيب مستقبلًا |

**المبدأ الحاكم:** النظام يُقاس بنسبة الإشارة إلى الضوضاء، لا بعدد البطاقات. لو سحبنا 280 منشورًا وخرجت 40 بطاقة فقط — هذا نجاح لا فشل.

**ملاحظة على مصطلح «الأتمتة لاحقًا»:** صممت كل شيء تحت افتراض أن الطبقة الوحيدة التي ستتغير عند الانتقال للسحابة هي `SourceAdapter`. كل ما فوقها (التصنيف، الترتيب، منع التكرار، الواجهة) لن يُعاد كتابته.

## 2. المعمارية المقترحة

سبع طبقات مستقلة، كل واحدة قابلة للاستبدال دون لمس الأخرى:

```
├──────────────────────────────────────────────────────────┤
│  6. View Engine       Filter Engine · Search · Ranking    │
│                       (دوال نقية: (items, state) → items) │
├──────────────────────────────────────────────────────────┤
│  5. Personalization   Likes · Bookmarks · Preference      │
│                       Vector · Relevance Scoring          │
├──────────────────────────────────────────────────────────┤
│  4. Store             content.json · authors.json ·       │
│                       taxonomy.json · user_state.json     │
├──────────────────────────────────────────────────────────┤
│  3. Processing        Dedup Clustering · Serial Assigner  │
├──────────────────────────────────────────────────────────┤
│  2. AI Analysis       Importance Gate → Classify →        │
│                       Arabic Title/Summary → Explain      │
├──────────────────────────────────────────────────────────┤

```

### قاعدة العقود بين الطبقات

كل Adapter — مهما كان المصدر — ملزم بإخراج نفس الشكل:

```
RawItem {
  source_type, source_url, source_native_id,
  author_ref, published_at, raw_text,
  media[], links[], metrics{}, raw_payload
}
```

هذا يعني أن إضافة مصدر جديد لاحقًا (Reddit, Hacker News, RSS, بودكاست) = كتابة ملف واحد فقط.

وطبقة الـ AI Analysis لا تعرف من أين جاء المحتوى إطلاقًا. تستقبل `RawItem` وتُخرج `Analysis`. هذا الفصل هو ما يمنع المشروع من التحول إلى Monolith.

### أين ينفَّذ كل شيء (المرحلة الحالية vs السحابة)

| الطبقة | الآن (Prototype) | لاحقًا (Cloud) |
|---|---|---|
| Source Adapters | جلسة متصفحك عبر GraphQL | Apify Actors / API مدفوع |
| AI Analysis | أنا داخل هذه الجلسة | Claude API عبر cron يومي |
| Store | ملفات JSON | Postgres / Supabase |
| View + UI | HTML واحد قائم بذاته | نفس الكود منقولًا إلى React |

### 3.2 التعديلات الستة على مخططك، ولماذا

| # | التعديل | السبب |
|---|---|---|
| 1 | دمج `companies` + `products` في `entities[]` | Cursor شركة ومنتج في آن. الفصل يُنتج تكرارًا وتناقضًا. الكيان الواحد له `type: company\|product\|model\|tool` وعلاقة `parent` (Codex ← OpenAI)، فيصبح فلتر «كل تحديثات OpenAI» يشمل ChatGPT وCodex تلقائيًا |
| 2 | `liked_by_me` و `bookmarks` خارج `ContentItem` | حالتك الشخصية تتغيّر كثيرًا، والمحتوى لا يتغير. خلطهما يعني إعادة كتابة ملف المحتوى كله عند كل ضغطة Like. الفصل يسمح لاحقًا بمزامنة تفضيلاتك عبر أجهزة دون لمس المحتوى |
| 3 | `ranking_score` محسوب لا مخزَّن | لأنه يعتمد على تفضيلاتك المتغيرة وعلى عمر المنشور. تخزينه يعني أنه يصبح خاطئًا بعد ساعة |
| 4 | إضافة `metrics_captured_at` | 4.4M مشاهدة الآن ≠ 4.4M بعد أسبوع. بدون هذا الحقل ستكون الأرقام كذبة صامتة |
| 5 | إضافة `confidence` و `importance_tier` | تحتاج أن تعرف متى كان التحليل غير واثق، وأن تفلتر الضوضاء بمستوى لا برقم |
| 6 | إضافة `glossary[]` و `why_it_matters` كحقول مستقلة | طلبتهما في صفحة التفاصيل؛ جعلهما حقلين منفصلين يسمح بعرضهما كأقسام ثابتة بدل دفنهما داخل نص |

### 3.3 الكيانات الأخرى

**`Author`** — `id, handle, display_name, avatar_url, bio_ar, bio_original, account_type (person|company|product|media), is_arabic, location, website, profile_url, other_profiles[], primary_domains[], tracked_entities[], follower_count, followers_captured_at, is_watched, added_via, linkedin_url|null, linkedin_confidence`

> **بخصوص LinkedIn:** لن أضيف رابطًا إلا إذا كان مذكورًا صراحة في البايو أو في موقع الشخص. لن أخمّن أبدًا. الحقل يبقى `null` وواضحًا، ويظهر في الواجهة كـ «غير متوفر» لا كفراغ.

**`Entity`** — `id, name, name_ar, type, parent_id, aliases[], logo_url, official_accounts[]`

**`Cluster`** — `id, canonical_item_id, member_item_ids[], topic_signature, first_seen_at, source_count`

**`UserState`** *(ملف منفصل)* — `likes[], bookmarks: {collection_id: [item_ids]}, collections[], views[], dismissed[], preference_vector`

**`Collection`** — `id, name, color, icon, item_count, created_at, shared_token|null`

### 3.4 الرقم التسلسلي

- عدّاد عالمي واحد `global_serial_counter` في ملف الحالة.
- يُمنح **لحظة قبول** العنصر (بعد اجتياز بوابة الأهمية) — لا عند السحب.
- لا يُعاد استخدامه أبدًا حتى لو حذفت البطاقة (الحذف = `status: deleted`، والرقم يبقى محجوزًا).
- عند دمج تكرار: البطاقة الممثِّلة تحتفظ برقمها، والمصادر الأخرى تُدرج داخلها بلا أرقام مستقلة.
- ظاهر في أعلى كل بطاقة وقابل للنسخ بضغطة، حتى تقول لي مباشرة: «البطاقة 124 عنوانها غير واضح».

## 5. الفلاتر

كلها **تراكمية (AND بين المحاور، OR داخل المحور)**. أي: اختيار `MCP` + `Tutorial` داخل «نوع المحتوى» = أحدهما؛ وإضافة `Anthropic` من محور الكيانات = يجب أن يتحقق الشرطان معًا.

| المجموعة | الشكل | القيم |
|---|---|---|
| الزمن | Chips + منتقي مدى | آخر 24 ساعة · 7 أيام · 30 يومًا · مدى مخصص |
| نوع المحتوى | Chips متعددة | كل قيم المحور A |
| المجال | Chips متعددة | كل قيم المحور B |
| الكيان | Chips هرمية | شركة تجلب منتجاتها |
| طبيعة التغيير | Chips متعددة | كل قيم المحور D |
| المصدر | Chips | X · YouTube · GitHub · Website · Article |
| اللغة | Toggle ثلاثي | الكل · عربي · أجنبي |
| الأهمية | Toggle | مهم فقط · مهم + مفيد · الكل (شامل الضوضاء) |
| تفضيلاتي | Chips | Liked · Bookmarked · Recommended · لم أقرأه بعد |
| المجموعة | Dropdown | Drive7 · Personal · Marketing · … |
| الترتيب | Segmented | ذكي · الأحدث · الأعلى تفاعلًا · Likes · Reposts · Views |
| البحث | حقل نصي | يبحث في العنوان والملخص والنص الأصلي والوسوم واسم الكاتب |

**عناصر تجربة أساسية:** شريط الفلاتر النشطة قابل للإزالة فردًا فردًا · عدّاد نتائج حي · حفظ مجموعة فلاتر باسم (Saved View) · حالة الفلاتر في الـ URL حتى لا تضيع عند الرجوع من صفحة التفاصيل.

## 6. منطق الترتيب (Ranking)

```
ranking_score =
      0.35 × importance_score
    + 0.25 × engagement_score
    + 0.30 × personal_relevance_score
    + 0.10 × freshness_score
```

| المكوّن | كيف يُحسب |
|---|---|
| `importance` | حكم طبقة الـ AI: جِدّة المعلومة، قابليتها للتنفيذ، مصدرها الأول أم منقول |
| `engagement` | تطبيع **داخل شريحة الحساب** — 500 لايك من حساب بـ 13 ألف متابع أقوى من 500 لايك من حساب بـ 5 ملايين. بدون هذا التطبيع ستحتكر الحسابات الكبيرة الصفحة الأولى |
| `personal_relevance` | تشابه بين وسوم البطاقة و«متجه تفضيلاتك» المبني من Likes وBookmarks وزمن القراءة |
| `freshness` | تحلل زمني نصف عمره 48 ساعة — يمنع تجمّد الصفحة الأولى على خبر قديم مرتفع التفاعل |

**نقطة صريحة:** في الجولة الأولى `personal_relevance` = 0 لأنك لم تضغط Like بعد. سيبدأ وزنه بالظهور بعد ~20 إعجابًا. لن أدّعي أن النظام «يتعلم» من اليوم الأول — هذا غير صحيح. سيبدأ محايدًا ثم يتحسن.

## 7. استراتيجية منع التكرار

ثلاث مراحل متتالية، من الأرخص إلى الأغلى:

| المرحلة | الطريقة | تلتقط |
|---|---|---|
| 1. مطابقة صلبة | نفس `source_url` بعد التطبيع، أو نفس رابط خارجي مستهدف (بعد فك اختصار t.co) | إعادة نشر الرابط نفسه |
| 2. بصمة موضوعية | `entity + change_type + نافذة 72 ساعة` → توقيع مبدئي | ست تغريدات عن تحديث ChatGPT نفسه |
| 3. حكم دلالي | مقارنة الادعاء الجوهري للبطاقات المرشحة داخل التوقيع نفسه | إعلان واحد بصياغات مختلفة تمامًا |

**اختيار البطاقة الممثِّلة**، بالترتيب:
1. المصدر الرسمي (حساب الشركة نفسه) يفوز دائمًا على الناقل.
2. ثم الأغنى معلومة (رابط مباشر للإعلان، تفاصيل تقنية).
3. ثم الأعلى تفاعلًا.
4. عند التعادل: الأقدم زمنًا (السبق).

**شكل العرض:** بطاقة واحدة، وفي أسفلها شريط «ذكرها أيضًا: 5 مصادر» يفتح قائمة الروابط والأشخاص. البطاقات المدموجة لا تحصل على أرقام تسلسلية مستقلة.

**حماية مهمة:** الدمج قابل للتراجع. لو دمجت شيئين لا يجب دمجهما، تضغط «فصل» فتعود بطاقتين — لأن خطأ الدمج يخفي معلومة، وهذا أسوأ من التكرار.

## 8. كيف سأتعامل مع كل مصدر

| المصدر | الطريقة | ما أستخرجه |
|---|---|---|
| **X — حساب** | GraphQL `UserTweets` عبر جلستك | آخر N منشورًا + كل المقاييس + الروابط + النص الكامل للثريد |
| **X — قائمة** | GraphQL `ListMembers` ← ثم كل عضو | ✅ اختُبر بنجاح اليوم |
| **X — تغريدة مفردة** | `TweetDetail` | التغريدة + الردود + المقتبَس. ثم أسألك: أضيف صاحبها للمراقبة؟ |
| **X — Quote Tweet** | نفس الاستدعاء | أفهم الأصل + التعليق + **العلاقة بينهما** (تأييد؟ نقد؟ إضافة؟) وأشرحها في التفاصيل |
| **YouTube — فيديو** | صفحة الفيديو + النص التلقائي إن وُجد | عنوان، قناة، تاريخ، وصف، روابط، نقاط رئيسية، Timestamps للفصول المُعلنة |
| **YouTube — قناة** | آخر فيديوهات | بطاقة لكل فيديو يتجاوز بوابة الأهمية |
| **GitHub** | GitHub API | الوصف، README، Stars، Forks، اللغة، آخر تحديث، الرخصة، **تصنيف: Tool/MCP/Skill/Library/Framework/Agent/Example** |
| **موقع / أداة** | جلب الصفحة + صفحات فرعية (pricing, docs) | ما المشكلة التي تحلها، لمن، أهم الوظائف، هل فيها API، هل لها MCP، هل لها GitHub، مجاني أم مدفوع |
| **مقال** | جلب النص | ملخص عربي + شرح موسّع + تصنيف مزدوج (Articles + الموضوع) |

**الردود والتعليقات:** لا أنسخها. أستخرج فقط ستة أنواع: تصحيح · معلومة إضافية · رابط مفيد · اعتراض تقني · تجربة مستخدم · أداة بديلة. وإن لم يوجد أي منها، **لا يظهر القسم أصلًا**.

## 10. المخاطر والقيود — بصراحة

| # | المشكلة | تقييمي | البديل المقترح |
|---|---|---|---|
| 1 | **شروط استخدام X تمنع السحب الآلي** | استخدام جلستك الشخصية لقراءة محتوى تراه أصلًا = منطقة رمادية، لا استخدام تجاري ولا إعادة نشر. المخاطرة الواقعية منخفضة عند معدلات هادئة، لكنها ليست صفرًا | إبقاء المعدل هادئًا · عدم إعادة النشر · الانتقال لمصدر مرخّص عند التوسع |
| 2 | **الجهاز مفتوح** | يناقض هدفك «يعمل دون جهازي» | Apify للأتمتة السحابية — وقد اخترت هذا المسار |
| 3 | **هشاشة الطريقة** | X تغيّر بنيتها الداخلية دوريًا | اكتشاف ديناميكي + تنبيه واضح عند الفشل بدل تعطل صامت |
| 4 | **تكلفة تحليل الردود** | طلب منفصل لكل منشور | اخترت: الردود للبطاقات المهمة فقط ✅ |
| 5 | **جودة التصنيف الذاتي** | لن تكون 100% من أول جولة | كل بطاقة تحمل رقمًا تسلسليًا، فتقول لي «البطاقة 47 تصنيفها خطأ» ونصحح القاعدة لا البطاقة وحدها |
| 6 | **بيانات شخصية** | تخزين صور وبايوهات وأسماء | استخدام شخصي فقط · بلا مشاركة عامة · حذف عند الطلب |
| 7 | **«التعلم من الإعجاب» ليس سحرًا** | 20 إعجابًا لا تكفي لبناء نموذج | البداية بترتيب محايد + إظهار سبب الترشيح («لأنك أعجبت بـ 3 بطاقات عن MCP») حتى تبقى شفافة |
| 8 | **مصداقية المقاييس** | الأرقام لقطة لحظية | حقل `metrics_captured_at` + عرضه في التفاصيل |
| 9 | **الترجمة الركيكة** | الترجمة الحرفية تقتل المعنى التقني | إعادة صياغة لا ترجمة · إبقاء MCP/API/Agent/RAG/Embedding/Fine-tuning بالإنجليزية |
| 10 | **تضخم البيانات** | آلاف البطاقات بعد أشهر | البحث والفلاتر مصممة من اليوم الأول للعمل على آلاف العناصر، والانتقال لقاعدة بيانات حقيقية عند تجاوز ~2000 بطاقة |

### نقطة اعترضتُ عليها في طلبك

طلبت **«روابط الردود المهمة»** — رابط الرد المفرد في X متاح تقنيًا، لكنه يتطلب سحب صفحة الردود كاملة لكل منشور. مع تفعيل ذلك لكل بطاقة، الجولة الواحدة تتضاعف زمنيًا عدة مرات وترتفع مخاطر التوقف المؤقت. لهذا اقترحت — ووافقت — قصره على البطاقات المهمة فقط.
